## Namespaces

Namespaces create isolated memory spaces. Use them to separate memories by user, project, or any logical boundary. The namespace is part of the URL (`/ns/{namespace}/...`), so every SDK call takes it as a top-level key.

### Adding Memories to a Namespace

```typescript
await supermemory.add("user_123", {
  content: "Meeting notes from Q1 planning",
});
```

### Searching a Namespace

```typescript
const results = await supermemory.search("user_123", {
  query: "planning notes",
  searchMode: "chunks",
});
```

<Note>
Each search is scoped to a single namespace. Passing `namespace: "user_123"` restricts results to memories stored in that namespace.
</Note>

### Recommended patterns

| Pattern | Example | Use Case |
|---------|---------|----------|
| User isolation | `user_{userId}` | Per-user memories |
| Project grouping | `project_{projectId}` | Project-specific content |
| Hierarchical | `org_{orgId}_team_{teamId}` | Multi-level organization |

<AccordionGroup>
  <Accordion title="More Namespace Examples">
    ```typescript
    // Multi-tenant SaaS - isolate by organization and user
    await supermemory.add("org_acme_user_john", {
      content: "Company policy document",
    });

    // Search only within that user's org context
    const results = await supermemory.search("org_acme_user_john", {
      query: "vacation policy",
      searchMode: "chunks",
    });

    // Project-based isolation
    await supermemory.add("project_mobile_app", {
      content: "Sprint 5 retrospective notes",
    });

    // Time-based segmentation
    await supermemory.add("user_cfo_2024_q1", {
      content: "Q1 2024 financial report",
    });
    ```

    The namespace is a path parameter on every v5 call (`add`, `search`, `list`, `profile`, `documents.*`). There is no array form; one request touches one namespace.
  </Accordion>
</AccordionGroup>

## Metadata

Metadata lets you attach custom properties to memories and filter by them later.

### Adding memories with metadata

```typescript
await supermemory.add("user_123", {
  content: "Technical design document for auth system",
  metadata: {
    category: "engineering",
    priority: "high",
    year: 2024,
  },
});
```

### Searching with a Filter

A filter is a typed expression. One condition is an object with `field`, `operator`, and `value`. Several conditions are combined with an `and` or `or` node that lists them in `operands`:

```typescript
const results = await supermemory.search("user_123", {
  query: "design document",
  filter: {
    operator: "and",
    operands: [
      { field: "category", operator: "eq", value: "engineering" },
      { field: "priority", operator: "eq", value: "high" },
    ],
  },
  searchMode: "chunks",
});
```

A single condition needs no wrapper:

```typescript
filter: { field: "status", operator: "eq", value: "published" }
```

### Operators

| Operator | Value type | Example |
|----------|------------|---------|
| `eq`, `neq` | string, number, boolean | `{ field: "status", operator: "eq", value: "published" }` |
| `gt`, `gte`, `lt`, `lte` | number | `{ field: "priority", operator: "gte", value: 5 }` |
| `contains`, `notContains` | string | `{ field: "title", operator: "contains", value: "react" }` |
| `arrayContains`, `arrayNotContains` | string | `{ field: "tags", operator: "arrayContains", value: "important" }` |

String conditions accept an optional `caseSensitive` boolean. Numeric values are JSON numbers, not numeric strings.

### Combining filters

Nest `and` and `or` nodes for complex queries:

```typescript
const results = await supermemory.search("user_123", {
  query: "meeting notes",
  filter: {
    operator: "and",
    operands: [
      { field: "type", operator: "eq", value: "meeting" },
      {
        operator: "or",
        operands: [
          { field: "team", operator: "eq", value: "engineering" },
          { field: "team", operator: "eq", value: "product" },
        ],
      },
    ],
  },
  searchMode: "chunks",
});
```

### Excluding results

Use the negative operators (`neq`, `notContains`, `arrayNotContains`) to exclude matches:

```typescript
const results = await supermemory.search("user_123", {
  query: "documentation",
  filter: { field: "status", operator: "neq", value: "draft" },
  searchMode: "chunks",
});
```

### Filters Beyond Search

The same `filter` expression works on list and profile calls:

```typescript
// Page through matching documents
const { documents, pagination } = await supermemory.list("user_123", "documents", {
  filter: { field: "category", operator: "eq", value: "engineering" },
});

// Build the profile only from matching memories
const { profile } = await supermemory.profile("user_123", {
  filter: { field: "source", operator: "eq", value: "onboarding" },
});
```

## Quick reference

### When adding memories

```typescript
await supermemory.add("user_123", { // Isolation
  content: "Your content here",
  metadata: { key: "value" },         // Custom properties
});
```

### When searching

```typescript
const results = await supermemory.search("user_123", { // Scopes results to this namespace
  query: "search query",
  filter: { field: "status", operator: "eq", value: "published" }, // Optional
  searchMode: "chunks",
});
```

### Metadata key rules

- Allowed characters: `a-z`, `A-Z`, `0-9`, `_`, `-`, `.`
- Max length: 64 characters
- No spaces or special characters
- Keys are literal: `customer.plan` is one key named `customer.plan`, not a nested path

### Query complexity limits

- Maximum 5 levels of nested `and`/`or` expressions
- Maximum 200 operands per logical group

<Note>
If you need more conditions than these limits allow, break your query into multiple requests or use broader search terms with post-processing.
</Note>

### Reading One Document's Chunks

Scoping a search to a single document (`docId`) is not part of v5. To work with the chunks of one long document, fetch the document with its chunks attached:

```typescript
const doc = await supermemory.documents.get("user_123", "doc_123", {
  include: ["chunks"],
});
```
